# CinderOS Voice

CinderOS should read like notes from the person who maintains it.

Use short sentences. Name the thing being checked or changed. Say when a feature is manual, risky, or still untested. Prefer the words you would use while setting up the machine yourself.

Good CinderOS text:

- says what the action does
- keeps service changes explicit
- admits when hardware still needs testing
- avoids hype
- avoids vague polish

Use labels like:

- `Check games`
- `Save my setup`
- `Open projects`
- `What is installed`
- `System check`

When writing docs, keep the reader close to the machine. Mention the command, the file, the backup, the boot entry, or the service. Skip broad claims.
